# シミュレーション仕様

## 1. 状態の分離

世界状態Wは、位置、物の所在と状態、設備、現在の作用、時刻を持ちます。住民の認識Bは、その人が観測・伝聞・推論で得た命題、根拠、優先順位を持ちます。行動規則PはBと現在観測できる範囲から行為Aを選び、遷移Tが複数の行為を世界へ適用します。

住民の判断規則へWの全体を直接渡しません。物理的な実行可能性と結果の判定だけは世界の事実を参照します。「知らずに鍵のない扉を開けようとする」は許され、「見ていない鍵の場所を知る」は許されません。主人公の所持品の真の識別情報を、未確認の会話・手帳にそのまま表示しません。

プレイヤーの頭の中の仮説はシミュレーション状態として推定しません。手帳へ明示的に書いた推測を保存する場合も、世界の事実や住民の認識を変える効果はありません。

## 2. 更新の単位と順序

初期実装は100ミリ秒の固定更新を採用し、描画はその間を補間します。1日は14,400更新が試作値です。実行速度を変えても同じ入力列と初期状態なら同じ結果を得られることを要求します。

各更新は次の順に処理します。

1. 入力をコマンドとして採番し、前更新で確定した出来事の配信と予定された到着を処理する。
2. その時点の世界から視認・聴取・接触・掲示閲覧を判定し、受け取った主体の認識を更新する。
3. 全住民が同じ更新開始時点のスナップショットから次の行為を提案する。
4. 実行中行為の持続条件を検査し、中止・復旧が必要なものを優先する。新規行為の競合と予約を一括調停する。
5. 移動・作業を進め、物の受渡し、消費、設備の変化などを一つの整合した更新として確定する。
6. 達成に対応する実際の出来事を検査し、達成履歴と達成後の状態への移行を一度だけ確定する。
7. 出来事・情報の配信予定・保存可能なスナップショットを作る。認識に基づく次の選択は次更新で行う。

同じ更新で橋が閉じる提案と船が通過する提案が出た場合、配列の処理順で片方を成功させません。通船中の保持予約と持続条件によって閉鎖を拒否するか、規定した待機・復旧へ進めます。物理条件が区間の途中で破れる行為は、その区間の終点だけを見て成功にしません。通過領域と保持区間の検査を行います。

開始と完了を一つの更新で何段も連鎖させる処理は禁止します。即時の受渡しは一つのトランザクションとして処理できても、その結果を聞いた別人の移動完了まで瞬時に進めません。

## 3. 観測と伝達

出来事には発生者、対象、場所、時刻、意味、因果元を記録します。誰が知るかは別に判定します。視認には同じ場所・可視範囲・遮蔽物、聴取には距離・部屋の接続・騒音・合図の種類を用います。画面に描画されていない住民にも同じ観測規則を適用します。

会話では話者が述べた命題と、その根拠を受け手へ渡します。受け手が聞いた、理解した、信用した、賛成した、役を引き受けた、は別の結果です。嘘や誤解も認識として保持でき、客観的事実を自動的に書き換えません。

札を置いた時点で全員へ配信しません。読める場所へ来て実際に読んだ住民が知ります。注文品の受渡しは所持を変えますが、受領の返事が届くまでメイベルが配達完了を知ることにはなりません。

約束は内容と版を持ちます。待ち合わせ先を一人へ変更しただけなら、相手は旧版で動き続けます。共同作業の開始には、参加者が同一の手順・合図・中止条件を受け入れたことを要求します。全員の認識を共通変数への代入で同期しません。

## 4. 行為と資源

行為には実行者、場所、所要時間、開始条件、持続条件、終了条件、使う手、道具、占有場所、消費量、成功結果、中断結果、復旧行為を持たせます。移動も行為です。画面外へ出た時に目的地へ瞬間移動させません。

主人公と住民は左右の手を個別に予約できます。両手で支える作業中に物を渡す等の競合は開始前に判定します。持ち物欄に収納することと、今手で保持することを分けます。大きな荷・支柱・操作点は収納できる小物として扱いません。

複数資源を必要とする行為は、全部を確保できる場合にだけ予約します。一部だけ保持して他の資源を待つ方式を避け、相互予約のデッドロックを作りません。実行中の保持予約を優先し、新規予約は要求時刻と採番順で決めます。拒否された行為は理由を記録し、再検査時刻を持ちます。完了・中止で不要な予約を必ず解放します。

所有者と現在の所持者は別です。借用は所有権を移しません。一つの物は一時点に一つの場所、所持者、容器、設備への組込み先のいずれかを持ちます。受渡しは送り手から減らす処理と受け手へ増やす処理をまとめて確定し、複製や消失を防ぎます。

消費は該当する工程が成立した時に一度だけ適用します。開始時に消費する必要がある行為はその点を明記し、中断時に戻す量と戻せない量を区別します。同じ完了イベントの再受信で二重消費・二重報酬を起こしません。

## 5. 住民の行動規則

汎用的な自律AIや外部LLMを必須にせず、条件付き規則と有限の状態遷移で実装します。目的、認識、習慣、予定を参照し、なぜその方法を選んだかを開発ログで確認できます。

行動様式は待機、再試行、探索、周回、往復、追跡、回避、過剰な維持、隠れる、競合、進行、共同実行、達成後の生活を組み合わせます。「他者を妨げる」は独立の作用として記述します。同じ場所で作業していても進捗していれば滞留ではありません。

失敗から学ぶ規則も、学ばずに周回する理由も人物データへ記載します。たとえばベンは逃げる犬を「追い方が足りない」と解釈し、停止の効果を観測するか説明を受け入れない限り追跡を続けます。物理的に犬がいなくなれば、少なくとも見失ったことに応答し、何もない所へ追跡アニメーションを流し続けません。

## 6. 三種類の共同場面

### 同席

夕食・茶・迎えは、別々の準備と移動の後、必要な相手が同じ場所へ集まり実際の行為をしたことで成立します。準備が早い人は通常の生活をしながら次の機会を待てます。食べ物の保管・温め直しなども、必要ならデータに持たせます。

夕食は三人の参加した共通場面に、食事開始とキットの語りを含め、その完了でC001〜C003を一括記録します。荷下ろし完了や帰宅可能だけで三人を達成にしません。

### 持続する同時作用

運河では水位、橋の開放、操船、連絡の条件を通過区間に保ちます。準備・集合・確認・開始合図・実行・復旧・終了確認を別の段階にします。主人公が別の画面へ移っても、連絡設備と担当者が成立していれば続けます。主人公が引き受けた役を離れた場合は、その役の持続条件が破れます。

中止時は、設定した待機位置で船を止め、必要な保持予約を復旧完了まで残します。失敗した瞬間に全員の予約を解放して橋を閉じる処理にはしません。C037・C039は設備の復帰、C038は荷の受渡しと係留で、それぞれ達成します。

### 支えを保つ置換

本を使うビー玉遊びは、代わりの板を据える、支えが成立したと確認する、本を抜く、という順を要求します。板を持っているだけでは支えになりません。場所・手・支えの接続を検査し、置換中に支えが失われる場合は中断と反応を返します。

## 7. 達成後の接続

達成イベントには、生活目的の実行証拠と、残る資源・サービスを対応付けます。実装前の検査で、未達成人物の必須経路が達成者の問題用判断を必要としないことを確認します。達成済み人物の通常の挨拶・受取り・合意済み出演は可能です。

達成後に新しい説得が必要になる原文の接続は、[設計判断](decisions.md)の補足に従い、事前の合意・受取口・通常応対へ具体化します。生活目的を果たした後に、依存が残っているという都合だけで達成を保留する処理は採りません。必要な残存処理を、目的が果たされる前または同じトランザクションで成立させます。

通常サービスの利用条件に達成人数や新しい困り事を足しません。通常時間外であれば次の営業機会か設置済みの受渡し口を使えます。退場する人物が後続の必須品や唯一の情報を持ち去る状態は、データ検証で不合格とします。

## 8. 再現性と記録

開始状態、コンテンツ版、乱数シード、時刻付きコマンド列から再現できる構造にします。演出用乱数とゲーム状態を変える乱数を分離します。ログは原因の追跡用であり、毎回全履歴を再生しなければ起動できる構成にはしません。保存は完全なスナップショットと必要な参照イベントを持ちます。

開発ログは、選択した規則、読んだ認識、予約失敗、持続条件の破れ、達成証拠、情報の配送先を追えるようにします。通常プレイ画面に内部変数名を表示しません。
