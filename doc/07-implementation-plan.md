# 実装計画

## 最優先の順序

2026-10-17の追加指示により、現画面を全体マップの制作途中の一角と位置づけます。初期の三棟・33地点では全体マップとしても不足しています。戸越銀座の商店街と周辺住宅街を規模の基準に、全体配置・棟・住戸・店舗・通路・設備を拡張し、ドット絵素材を適用します。まず全体マップ上で100人・十場面・別解・保存・結末までを作りきり、その後にMOONを基準とするエリア別の通常探索を制作します。

Phaser導入はエリア探索へ移る段階の検討事項です。全体マップ完成の前にエンジン移行を必須化しません。[全体マップ・エリア探索の制作方針](08-world-map-and-scenes.md) と [ハンドオフ](handoff.md) の順序に従います。

## 1. 配布と技術構成

先行対象はPCブラウザです。公開URLを開けば遊べる静的Webアプリとし、利用者によるNode.jsのインストールや開発サーバー起動をプレイ手順にしません。公開先は実装後にリポジトリの設定と合わせて決めます。GitHub上のビルド配布と公開ホスティングは分けて扱います。

初期方針はTypeScript、Canvas 2Dによる街の描画、HTML/CSSによる会話・手帳・メニュー、ビルド済みの静的ファイルです。型検査はTypeScript 5.9.3、ビルドはesbuild 0.25.11を固定しています。シナリオの判定に外部APIやLLMを必須としません。

シミュレーションの中核はDOM・Canvas・ブラウザの実時間に依存させず、ヘッドレスで動かします。入力はコマンド、出力は世界状態の読み取り用スナップショットと出来事にします。描画が見えなくても生活が進むことと、操作の再現性を両立させます。

## 2. 実装先の分担

以下は完成時の構成です。現在は `src/game/` にCanvas描画と通常UIをまとめ、`index.html` にビルドしています。開発検査画面は `inspector.html` です。`presentation/` と `ui/` への分割、完成素材は後続作業です。

- `src/core/`: 時刻、状態遷移、認識、行為、予約、物、達成、出来事。
- `src/content/`: 検証済みの人物・場所・物・場面・会話定義。
- `src/presentation/`: 描画、アニメーション、音、状態からの見た目の選択。
- `src/ui/`: 入力、会話、持ち物、手帳、地図、保存画面。
- `src/storage/`: スナップショット、保存枠、検証、版の移行、書出し・読込み。
- `src/dev/`: 認識・因果・予約の検査画面。通常プレイへ正解情報を流さない。
- `public/assets/`: 完成素材と仮素材の参照先。
- `tests/`: 状態遷移、シナリオ再生、保存、画面操作の必要な検査。
- `doc/`: 本仕様、人物の補足、仕様変更、検証結果。

## 3. Phase 1: 実行基盤

型とデータ検証器、固定時計、観測と認識、決定規則、行為の開始・保持・終了、物の受渡し、資源予約、達成履歴、保存の基礎を実装します。表示は最小限の検査画面で構いません。

完了条件は、見ていない事実を知らない、二人が同じ物を同時に取得できない、中断後に復旧できる、同じ入力を再現できる、途中保存を復元できることです。人物を大量に追加する前に、ここを検証します。

## 4. Phase 2: 夕食を遊べる状態にする

対象11人と犬を実行データ化し、管理人室から廊下・階段・住戸・店・搬入口・活動室へ歩ける地図を作ります。靴回収、貸し靴、配達、メイベル自身の配達、荷下ろし、紙人形、夕食、達成後の返却をつなぎます。会話は同意と情報伝達を区別できるだけの全文を用意します。

完了条件は、公開可能な静的ビルドで操作でき、T01〜T07と該当する保存・提示検査を満たすことです。デバッグの達成ボタンや直接のフラグ操作で成功させた状態は完成に数えません。

## 4a. 全体マップの拡張とドット絵化

100人の居場所、仕事場、往復・巡回、受渡し先、隣接関係を全体配置へ結びつけます。最初の三棟を街の一角として残し、商店街の複数区間と脇道、住宅街、店の裏手、搬入路を追加します。地点を増やしてから人物の生活を押し込めるのでなく、各シナリオが成立する場所と接続を確保します。

建物・人物・小道具・設備・状態差分をドット絵で作り、全体マップへ適用します。移行元の53点とその原本を保持し、追加する素材も台帳へ登録します。全体マップの枠組みを先に整え、その上でPhase 3・4の人物と場面を完成させます。

## 5. Phase 3: 全体マップ上の同時作業

搬入路、関連する搬入係、独立した共用エレベーター、合図、持続条件、中止と復旧を実装します。活動室の本と板の置換も追加し、同席・同時作用・置換の三種類が同じ便利フラグへ潰れていないことを確認します。

完了条件は、途中で画面を離れる、中止する、保存する、再開する場合も、正常な通過と復旧が成立することです。前提の一部を変えた反事実テストでも違いが現れる必要があります。

## 6. Phase 4: 全体マップ上で十場面と100人を完成させる

まず住戸と郵便、睡眠と劇場、店と搬入口、共同工房と小劇場、印刷と送迎便の接続をそれぞれ通します。その後、各場面の残る人物を加えます。一人追加するごとに本文テンプレート、実行データ、会話、観察差分、達成後の契約、再生経路を揃えます。

追加する順番は実装上の都合であり、プレイの完了順にはしません。途中で特定場面の全員達成を仮の解錠条件にしたまま完成扱いにしません。

完了条件は、全100人の重複のない登録、全員到達経路、記載された別解、先後の検査、通常サービスへの移行、結末です。会話文や座標が未設定の人物は人数だけを埋めるために達成扱いにしません。

## 7. Phase 5: エリア別の通常探索と表現

全体マップ上で全100人、十場面、保存、結末が成立した後に着手します。MOONを基準に、部屋・廊下・中庭・店・仕事場を主人公が歩く通常探索シーンを作ります。出入口によるシーン遷移と局所の移動・接触・観察を、全体マップと同じ世界へ接続します。現行Canvasの継続とPhaserの導入を比較し、必要なら導入します。

全体マップ段階で作ったドット絵を基に、探索シーンで必要な密度と動作を整え、住民の仕草、歩く速さ、画面の密度、音、読める手掛かり、手帳の負担を調整します。一日の長さ・会話中の停止・移動速度はこの段階まで計測し、値を確定します。

完了条件は、説明を知らない人が観察から仮説を持ち、試した結果を理解でき、本人の達成を見届けられることです。論理検査とプレイテストの所見を別々に残します。

## 8. Phase 6: 配布

静的ビルドを作り、公開先で起動、素材読込み、セーブ、読込、更新後の互換性を確認します。ユーザー向けREADMEには実際に動作確認したURLと操作だけを記します。未検証のブラウザや端末へ対応済みと書きません。

## 9. 完成の数え方

進捗は「原文あり」「実行データ化」「動作確認」「解決順・保存確認」「表示確認」を分けます。仕様と原文保存、Phase 1基盤に加え、Phase 2夕食編の11人と犬を実装しています。本編11人の連続到達経路、別解、保存、通常画面の検査は [dinner-status.md](dinner-status.md) を参照してください。全100人の集合住宅版シナリオと53点のSVG素材があります。残る89人の行為実装、固有動作の完成素材、音、公開プレイURLは未完了です。11人の検査を全100人の確認へ読み替えないでください。
