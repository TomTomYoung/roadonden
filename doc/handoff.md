更新: 2026-10-17 / block-0.3.0。対象: TomTomYoung/roadonden。ユーザーの「シナリオ・素材含めて雑居ビル、アパート群に移行」に対応しました。

## 最優先の制作方針 — 2026-10-17の追加指示

**街の規模感は戸越銀座の商店街と周辺住宅街を基準にします。** 長い商店街を軸に、複数の区間・交差点・脇道・住宅街・雑居ビル群・アパート群・店の裏手と搬入路がつながる規模です。現在の三棟はその街の一角に位置づけます。参考となる通りの長さと、全体マップへ落とす方針は [制作方針の「街の規模と構成」](08-world-map-and-scenes.md#街の規模と構成--戸越銀座を基準にする) に記録しています。

現行の三棟の断面図は**全体マップの制作途中の一角**です。完成版の通常探索画面として扱いません。ユーザーから「このマップ全体なら足りてない」と明示されており、現在の雑居ビル一棟・アパート二棟・33地点では、100人の暮らしと全シナリオに必要な場所が不足しています。三棟・33地点・現在の画面寸法を完成時の上限にせず、必要な棟、住戸、店、仕事場、通路、待合、設備を全体マップ自体へ追加します。

**先に、拡張した全体マップ上でゲームを作りきります。** 全100人の配置と生活動線、十場面の行為・会話・別解・共同作業・達成後の暮らし、物と情報の接続、保存、結末までをこの段階で実装・検証します。背景と人物名を並べたことや、シナリオ文章が100人分あることを完成とは数えません。既存の小部屋へ残り89人を詰め込む作業ではありません。

**素材はドット絵へ移行します。** 全体マップの建物・人物・小道具・状態差分から適用し、後のエリア探索にも引き継ぎます。現行53点の滑らかなSVGは配置確認用の素材であり、指定されたドット絵への移行は未着手です。輪郭・色・動作を画素単位で作り、元の比率を保って表示します。既存素材は参照元として保存します。

**通常探索はMOONを基準とするエリアごとのシーン遷移です。** 部屋、廊下、中庭、店、仕事場などのエリアへ入り、主人公を動かして人物や物へ近づき、生活を観察・調査・会話する構成にします。全体マップの単なる拡大表示を通常探索の完成形にはしません。個別探索シーンの本格制作は、全体マップ上のゲームを完成させた後です。今の段階でエリア間の接続・入口・出口と持続する世界状態を整理しておきます。

Phaserはエリア探索を実装する際の候補です。既存Canvas継続案と、移動・接触・描画・素材・シーン遷移・配布の実装負担を比較し、必要なら導入します。現時点では未導入・未決定です。先にエンジン移行を始めることを全体マップ完成の前提にしません。住民の時間・認識・行為・達成・保存は既存のシミュレーションを正本とし、描画シーンの入退場で初期化しません。

場所の不足と具体的な完成条件は [全体マップ・エリア探索の制作方針](08-world-map-and-scenes.md) を参照してください。以下の現状報告と区別し、この追加指示を今後の作業順の基準にします。

## 現在の成果

雑居ビル一棟、アパートA/B棟、共用中庭、屋上の33地点で、夕食につながる11人と犬が暮らします。主人公も住民も共用廊下・階段を実際に歩きます。靴回収・貸し靴・配達、メイベル本人の配達、荷下ろし、紙人形と先行帰宅、家族の夕食、食後の返却と残る用事を維持しました。

全100人のシナリオを新舞台へ翻案し、名前とID、人間関係と別解を継承しています。運河・工場・学校・船旅・宿の設備や職務は搬入路・共同工房・活動室・送迎便・管理人室へ変更しています。残り89人はシナリオまでで、動作実装済みとは数えません。

53点のSVGを作成し、単体HTMLへ埋め込みました。三棟の断面、部屋の内装、階段、集合ポスト、搬入設備、服装と姿勢を描きます。地図の拡大は主人公を追い、元の比率を保ちます。音と全員の固有動作は未完了です。

## 起動・ファイル・保存

ルートの `index.html` を直接開きます。ネット接続や開発サーバーは不要です。公開ホスティングURLはまだありません。`inspector.html` は従来の基盤検査画面です。

- `src/content/block.ts`: 棟・階・部屋・内装・説明・33地点の接続と所要時間。
- `src/content/dinner.ts`: 11人と犬の会話・行為・認識・貸借。旧来の内部ID `quay` / `school` 等は安定参照のため残し、地名として表示しない。
- `src/game/renderer.ts`: 建物の断面描画、等比拡大、コマ切替え、状態差分。
- `scripts/make-block-assets.mjs` / `public/assets/manifest.json`: 素材の編集可能な生成元と台帳。`npm run assets` で再生成。
- `doc/adaptation/residents-001-100.md`: 現行の100人シナリオ。`doc/sources/` は原文のまま。
- `tests/block.test.mjs`: 移行に伴う経路・情報・保存・素材・人物IDの検査。

保存形式2、内容版 `block-0.3.0`、保存領域 `roadonden:block:v3:` です。旧版は `legacy/dinner-0.2.0.html` に完全なHTMLを残しています。保存画面から開けます。旧版の道の途中のセーブを新版の階段へ自動変換せず、旧版で続きを遊びます。旧保存領域 `roadonden:dinner:v2:` は触りません。

Node.js 24以上で `npm ci`、`npm run verify`。型検査、自動50件、単体HTMLのビルドを行います。Playwright環境では `scripts/browser-dinner-check.mjs` と `scripts/browser-check.mjs` を実行します。結果と検証上の限界は [dinner-status.md](dinner-status.md) を参照。生成済みHTMLとSVGもコミット対象です。

3. この全体マップ上で残る89人を実行データ化する。搬入路の共同作業、中止・復旧、初期から使える独立した共用エレベーター、本と板の置換を含め、十場面と相互接続を順次実装する。会話・移動・現物・情報・合意・達成後の応対を揃える。
