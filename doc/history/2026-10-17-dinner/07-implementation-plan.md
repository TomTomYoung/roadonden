# 実装計画

## 1. 配布と技術構成

先行対象はPCブラウザです。公開URLを開けば遊べる静的Webアプリとし、利用者によるNode.jsのインストールや開発サーバー起動をプレイ手順にしません。公開先は実装後にリポジトリの設定と合わせて決めます。今回の文書追加はゲームの公開ではありません。

初期方針はTypeScript、Canvas 2Dによる街の描画、HTML/CSSによる会話・手帳・メニュー、ビルド済みの静的ファイルです。型検査とビルドにはVite等の開発用ツールを用いる方針ですが、依存バージョンは実装時に確認して固定します。シナリオの判定に外部APIやLLMを必須としません。

シミュレーションの中核はDOM・Canvas・ブラウザの実時間に依存させず、ヘッドレスで動かします。入力はコマンド、出力は世界状態の読み取り用スナップショットと出来事にします。描画が見えなくても生活が進むことと、操作の再現性を両立させます。

## 2. 実装先の分担

以下は完成時の構成です。現在は `src/game/` にCanvas描画と通常UIをまとめ、`index.html` にビルドしています。開発検査画面は `inspector.html` です。`presentation/` と `ui/` への分割、完成素材は後続作業です。

- `src/core/`: 時刻、状態遷移、認識、行為、予約、物、達成、出来事。
- `src/content/`: 検証済みの人物・場所・物・場面・会話定義。
- `src/presentation/`: 描画、アニメーション、音、状態からの見た目の選択。
- `src/ui/`: 入力、会話、持ち物、手帳、地図、保存画面。
- `src/storage/`: スナップショット、保存枠、検証、版の移行、書出し・読込み。
- `src/dev/`: 認識・因果・予約の検査画面。通常プレイへ正解情報を流さない。
- `public/assets/`: 完成素材と仮素材の参照先。
- `tests/`: 状態遷移、シナリオ再生、保存、画面操作の必要な検査。
- `doc/`: 本仕様、人物の補足、仕様変更、検証結果。

## 3. Phase 1: 実行基盤

型とデータ検証器、固定時計、観測と認識、決定規則、行為の開始・保持・終了、物の受渡し、資源予約、達成履歴、保存の基礎を実装します。表示は最小限の検査画面で構いません。

完了条件は、見ていない事実を知らない、二人が同じ物を同時に取得できない、中断後に復旧できる、同じ入力を再現できる、途中保存を復元できることです。人物を大量に追加する前に、ここを検証します。

## 4. Phase 2: 夕食を遊べる状態にする

対象11人と犬を実行データ化し、宿から庭・家・店・岸・学校へ歩ける仮マップを作ります。靴回収、貸し靴、配達、メイベル自身の配達、荷下ろし、紙人形、夕食、達成後の返却をつなぎます。会話は同意と情報伝達を区別できるだけの全文を用意します。

完了条件は、公開可能な静的ビルドで操作でき、T01〜T07と該当する保存・提示検査を満たすことです。デバッグの達成ボタンや直接のフラグ操作で成功させた状態は完成に数えません。

## 5. Phase 3: 本当の同時作業

運河、関連する岸の人物、小舟、合図、持続条件、中止と復旧を実装します。学校の本と板の置換も追加し、同席・同時作用・置換の三種類が同じ便利フラグへ潰れていないことを確認します。

完了条件は、途中で画面を離れる、中止する、保存する、再開する場合も、正常な通過と復旧が成立することです。前提の一部を変えた反事実テストでも違いが現れる必要があります。

## 6. Phase 4: 十場面と100人

まず家と郵便、睡眠と劇場、市場と運河、工場と劇場、印刷と船旅の接続をそれぞれ通します。その後、各場面の残る人物を加えます。一人追加するごとに本文テンプレート、実行データ、会話、観察差分、達成後の契約、再生経路を揃えます。

追加する順番は実装上の都合であり、プレイの完了順にはしません。途中で特定場面の全員達成を仮の解錠条件にしたまま完成扱いにしません。

完了条件は、全100人の重複のない登録、全員到達経路、記載された別解、先後の検査、通常サービスへの移行、結末です。会話文や座標が未設定の人物は人数だけを埋めるために達成扱いにしません。

## 7. Phase 5: 表現と遊びの調整

仮素材を最終素材に置き換え、住民の仕草、歩く速さ、画面の密度、音、読める手掛かり、手帳の負担を調整します。一日の長さ・会話中の停止・移動速度はこの段階まで計測し、値を確定します。

完了条件は、説明を知らない人が観察から仮説を持ち、試した結果を理解でき、本人の達成を見届けられることです。論理検査とプレイテストの所見を別々に残します。

## 8. Phase 6: 配布

静的ビルドを作り、公開先で起動、素材読込み、セーブ、読込、更新後の互換性を確認します。ユーザー向けREADMEには実際に動作確認したURLと操作だけを記します。未検証のブラウザや端末へ対応済みと書きません。
